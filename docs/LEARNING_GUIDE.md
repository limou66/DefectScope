# 把项目变成自己能讲清楚的经历

这份代码是起点。简历中的“设计、实现、验证”应对应自己真正理解并亲手完成的工作。以下是建议的学习安排，不是已经发生的项目历时。

## 第 1–2 天：跑通与追踪

先运行轻量 demo，再运行真实 bottle 实验。挑一张正常图和异常图，顺着 features → model → metrics → reporting 追踪。亲自说明 16×16×14 和 16×16×192 两种特征的来源，画出内存库维度。保存自己修改过的运行记录。

## 第 3–4 天：讲清基线与校准

手工验证一个二维 nearest-neighbor 例子和一个含 ties 的 AUROC 例子。用 19、39、52 个校准分数计算最小 p 值，并解释为什么校准样本太少会无法报异常。理解为什么 test 不能参与 tune，为什么 p 值不是缺陷概率。

## 第 5–7 天：做一项自己的实质改进

选一个具体问题，不要一次堆很多模块。例如：

- 在新的真实类别上比较不同 memory size，并记录内存 / AUROC / 时间折中。
- 研究大面积污渍被光照模块吸收的问题：构建独立验证样本，比较掩码鲁棒拟合与当前 IRLS。
- 在固定拍摄场景下评估更细网格对小缺陷 IoU 的影响。
- 对近重复正常图按工件/采集批次划分，验证随机划分是否过于乐观。

先写实验假设和评测规则，再动代码。保留失败结果，在 Git 中分阶段提交，最终将你实际完成的改进写进 README 和简历。

## 第 8–10 天：补面试材料

用 3 分钟演示“正常图 → 缺陷图 → 切换策略 → 查看正常证据 → 展示失败案例”。每个数字都能指出来自哪个 CSV / JSON，而不是只背一张表。

## 常见追问与回答要点

1. 为什么不用 YOLO？本项目研究只有正常训练图的开放异常场景，缺陷类别与框标注不足；不是声称监督检测普遍无效。
2. 你训练了 ResNet 吗？没有，冻结 ImageNet backbone，训练的是正常分布、原型库和校准参数。
3. 创新在哪？独立实现与组合实验：空间可靠性融合、可关闭光照对齐、严格正常校准和可追溯证据；不声称经典思想是首创。
4. 为什么融合未必更好？分支可能高度相关、空间先验可能错位，简单空间分支在某些阈值下召回更高，门控也可能退化成等权。
5. AUROC 高是否说明可上线？不。仍有漏检、误报和域偏移；本项目仅验证一个真实类别，阈值、分辨率和样本量都有局限。
6. 为什么像素 AUROC 高、IoU 却低？正常背景占比、排序与固定阈值不同、粗网格边界扩散都会造成差异。
7. 正常证据是不是大模型解释？不是。它是最近邻参考 patch，不推断物理故障原因。
8. 为什么不加大模型？当前任务核心是视觉检测。若后续需要语言报告，可以让模型基于结构化检测证据生成摘要，但这应是另一个经验证模块。

## 岗位定位

该项目主要支持机器学习和视觉算法岗位。大模型算法岗常会深入询问 Transformer、训练优化、微调和数据工程；本项目没有提供这些经历，不应把它写成大模型项目。后续可另做有真实训练与评测的语言模型项目。
